# 회원 등록 요청 인증·화면 일관성 수정 — 2026-11-15

## 상황
사용자는 운영자 화면의 새 회원 등록 버튼에서 공통 403 안내를 받았다.
당시 실제 HTTP 요청·응답을 도구에서 조회할 수 없어 그 요청의 정확한 실패 사유는 미확인이다.
기존 서버는 CSRF 오류와 권한 부족에 같은 메시지를 사용해 구분할 수 없었다.

## 수정 코드
- static/app.js: 변경 요청마다 CSRF 조회. 서버가 CSRF_INVALID로 거절한 경우만 새 토큰과 같은 Idempotency-Key로 한 번 재시도. 권한 부족·네트워크 실패는 자동 재시도하지 않는다.
- WebSecurity.java: CSRF_INVALID와 ACCESS_DENIED를 분리. CSRF 검증과 운영자 권한 검증은 유지한다.
- static/app.css: 회원 앱과 같은 배경 #FAF5ED, 카드 #FFFCF7, 강조 #AC5137, 글자 #3E302A, 테두리 #E9DED2. 입력 높이·모서리·버튼을 조정했다.
- static/index.html: Test Gym App으로 브랜드 표기를 맞추고 개발용 운영 데스크임을 명시했다. 이 페이지는 React Native 회원 앱 자체가 아니다.
- tools/start-app.ps1: 서버 실행 전에 최신 JAR 빌드. 이전 서버를 종료하지 않아 빌드가 실패하면 실행을 중단한다.
- tools/test-desk-api.mjs: 실제 app.js의 api 함수로 토큰 교체, 제한 재시도, 요청키 유지, 권한·네트워크 실패 무재시도 검증.
- MobileWebSecurityTest.java: 실제 CSRF 쿠키·헤더가 불일치하면 등록 업무 전에 403, 일치하면 운영자는 등록 경로 통과, 일반 회원은 권한 거절.

## 검증
웹 요청 회귀 5개 통과. 서버 테스트 13개 통과. JavaScript·시작 스크립트 구문 검사 통과.
현재 실행 중인 JAR의 파일 잠금 때문에 패키징 마지막 rename 단계는 실패했다.
기존 서버 창에서 Ctrl+C로 종료한 뒤 로컬실행.cmd를 재실행하면 새 절차가 다시 빌드한다.
실제 브라우저에서 회원 등록 성공과 변경한 시각 디자인의 확인은 재시작 후 필요하다.

## 회원 승인 입력창 호환성 수정
사용자가 회원 승인 버튼에서 prompt() is not supported 오류를 보고했다.
app.js의 window.prompt 호출을 제거하고 index.html에 사유 입력용 status-dialog를 추가했다.
승인과 이용 정지 모두 같은 페이지 내 모달을 사용한다.
공백 사유는 거절하고, 취소 시 API를 호출하지 않으며, 전송 중 중복 처리·닫기를 막는다.
전송 실패는 해당 모달 내부에 표시하고 성공하면 목록을 갱신한다.
공통 formHandler는 상태 변경·코드 발급 모달 각각의 data-form-notice에 오류를 표시한다.
JavaScript 구문 검사와 웹 회귀 테스트 11개(기존 요청 5 + 상태 변경 6)가 통과했다.
서버 실행 파일에 포함된 정적 리소스이므로 서버 재시작 후 Ctrl+F5가 필요하다.
실제 내장 브라우저에서의 모달 확인은 적용 후 필요하다.
