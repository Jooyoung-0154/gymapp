# 공통 로그인 및 회원 승인 변경

- 회원과 운영자는 mobile의 React 프런트엔드를 함께 사용한다.
- 회원 가입은 휴대전화번호와 비밀번호(12~128자)로 계정을 생성하고 승인을 요청한다.
- 승인 전 올바른 비밀번호로 로그인하면 승인 대기를 안내하며 세션을 발급하지 않는다.
- 운영자는 휴대전화번호와 비밀번호로 로그인한 뒤 회원 목록에서 승인한다. 승인 사유와 활성화 코드는 필요하지 않다.
- 승인 후 회원이 로그인하면 닉네임(2~20자)을 설정하고 회원 홈으로 이동한다.
- 닉네임은 표시 이름이다. 로그인 식별자는 휴대전화번호이며 닉네임 중복은 허용한다.
- 기존 이름이 있는 계정은 닉네임 설정을 다시 요구하지 않는다.
- 기존 관리 API 및 비밀번호 재설정 API는 유지한다. 공통 운영자 화면은 회원 목록과 가입 승인 기능을 제공한다.

## 실행

`tools/run-server.ps1 -Build`가 React 웹 내보내기와 서버 패키징을 수행한다. 기존 서버를 재시작하면 8080에서 공통 프런트엔드를 제공한다. Expo 개발은 기존 8081을 사용한다. 서버의 이전 static 로그인 화면은 패키징 대상에서 제외한다.

## 검증

타입 검사, 인증 클라이언트 테스트 및 서버 빌드를 수행한다. AuthFlowTest에 자체 가입 → 승인 대기 → 사유 없는 승인 → 로그인 → 닉네임 설정을 추가했다. 실행 환경에서 JDBC 네트워크 접근이 차단되어 DB 통합 테스트는 완료하지 못했다.

## 추가 점검

- 공통 화면 분기 테스트: 미로그인 → 로그인, 승인 회원의 닉네임 미설정 → 닉네임 화면, 설정 완료 → 회원앱, 운영자 → 운영자 화면.
- 가입·승인·운영자 추가 인증·닉네임 API 요청 테스트를 추가해 인증 클라이언트 8개 테스트를 통과했다.
- 타입 검사와 DB 비의존 서버 테스트 13개를 통과했다.
- 운영자 추가 인증 화면의 로그인 복귀가 가입 화면으로 잘못 이동하던 오류를 수정했다.
- 로그인 응답이 세션 종료 후 늦게 도착할 때 이전 계정을 복원하지 않도록 요청 순번 검사를 보완했다.
- 내장 브라우저는 세션 연결 오류, 직접 HTTP 접근은 로컬 소켓 권한 차단으로 실제 화면·DB 연동 점검을 수행하지 못했다.

## 운영자 로그인 추가 인증 제거

운영자 로그인은 비밀번호 확인 직후 운영자 세션을 발급한다. 기존 세션 시간 제한과 CSRF·역할 검사는 유지한다. 로컬실행.cmd 시작 시 004_operator_password_login.sql로 기존 세션 테이블의 MFA 필수 제약을 제거한다. 기존 코드 발급 API의 재인증 절차는 별도로 유지한다.
