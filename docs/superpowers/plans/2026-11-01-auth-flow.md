# Spring Boot 회원 등록·인증 구현 계획

범위: 운영자 비밀번호+TOTP 로그인 → 회원 등록·승인 → 일회용 코드 발급 → 회원 비밀번호 설정 → 로그인·본인 조회·로그아웃. 실행 DB는 gym_dev, 웹은 localhost 전용이다.

기술: Java 21, Spring Boot 3.5.16, Spring Security, JDBC, PostgreSQL. Node.js 서버는 만들지 않는다. 기존 테이블을 사용하고 challenge/요청 재전송 결과 테이블만 추가한다.

- [x] 최소권한 gym_app 계정·추가 마이그레이션 적용. 소유자·gym_private 권한 없음 확인.
- [x] 암호화·전화번호 HMAC·비밀번호 해시·TOTP 구현, 암호 도구 시험 4개 통과.
- [x] DB 세션·CSRF·로그인 제한·운영자 MFA·멱등 처리·암호화 사유/감사 구현.
- [x] 회원 등록/승인/코드/활성화/로그인과 한국어 화면 연결 코드 작성.
- [x] 실제 DB 통합 시험 8개: 정상 흐름, 중복 번호, 잘못된/만료/소비 코드, 권한, 실패 제한, 세션 회수, CSRF, 재전송·동시 등록/활성화 통과.
- [x] JAR 빌드 성공. 실행·확인 안내와 남은 범위를 server/README.md에 기록.
- [ ] 실제 서버 시작·bootstrap·브라우저 왕복 점검: 실행 권한 요청이 거절되어 미수행. 다른 경로로 실행을 우회하지 않았다.

개발 자격증명·암호키·운영자 초기 안내는 .validation/app에만 저장. 개발용 키 파일은 외부 KMS를 대신하지 않으므로 운영 배포로 간주하지 않는다. HTTP의 Secure 쿠키 예외는 명시적 로컬 설정에서만 허용하고 기본값은 Secure다. 운영자 MFA 완료 전 업무 접근 불가. 실제 DB 비밀번호는 사용자에게 요청하지 않는다.
