# QR 입장·출석·혼잡도 연결

## 사용 흐름

1. `로컬실행.cmd`로 최신 앱을 시작한다. 준비 스크립트가 `005_checkin_runtime.sql`과 앱 DB 권한을 적용한다.
2. 운영자가 관리자 → 운영 설정에서 시설 이름, 보통·혼잡 기준, 월~일 운영시간 또는 휴무를 저장한다.
3. 승인된 회원에게 유효한 시설 이용권을 등록한다.
4. 회원은 홈 → 입장 QR을 연다. 운영자는 별도 로그인 세션에서 관리자 → 입장 확인 → 스캐너 시작을 누른다.
5. 키보드 입력 방식의 QR 리더기로 QR을 읽거나, 회원 QR 화면에서 입장 코드를 표시해 붙여 넣고 입장 확인을 누른다.
6. 회원의 출석 달력과 홈의 2시간 입장 인원을 확인한다. 회원과 운영자는 다른 브라우저·시크릿 창 또는 앱으로 로그인한다.

## 구현 범위

- QR: 로그인 세션에 연결된 보안 난수, DB에는 HMAC 저장, 60초 유효·30초 갱신·성공 후 재사용 금지.
- 스캐너: 운영자 세션에 등록한 논리 기기만 허용. 리더기 키보드 입력·코드 붙여넣기 지원. 카메라 스캔과 독립 게이트 장비의 키 인증은 미구현.
- 입장: 계정·회원 승인, 회원 세션, 영업시간·날짜별 휴무, 휴회, 시설 이용권 또는 입장 가능한 PT 예약을 서버에서 검사.
- 기록: QR 소비·입장 요청·방문·혼잡도 구간을 같은 트랜잭션에서 확정. 회원 행 잠금과 DB 제약으로 동시 중복 방지.
- 중복: 같은 2시간 구간·같은 날짜에는 방문을 추가하지 않음. 재스캔으로 구간을 연장하지 않음. 정확히 2시간이면 새 구간. 자정 이후 재스캔은 새 날짜 출석.
- 통신 오류: 입장 확인 재시도는 동일 요청 키를 유지해 성공 결과를 대조. 확인되지 않은 응답을 성공으로 표시하지 않음.
- 혼잡도: 실제 구간의 고유 회원 수, 1분 갱신, 3분 지연 표시. 미설정·실패를 여유로 표시하지 않음.
- QR 화면은 백그라운드·통신 실패 시 숨김. 입장 확인 결과의 회원 이름은 5초 후 제거.
- 연속 출석·개근 보상과 실제 PT 예약 화면의 DB 연결은 후속 작업. 현재 관련 홈 요약은 예시로 표시.

## 검증과 한계

단위·MVC 테스트와 웹·Android·iOS 번들 검사를 수행했다. 실제 DB 통합 테스트는 도구 환경의 소켓 접근 제한으로 실행되지 않았으며, 리더기 실스캔·실기기 전체 흐름은 검증되지 않았다.
`CheckinFlowTest`는 실제 DB 검증용이며 각 테스트에서 생성한 운영 설정과 계정을 트랜잭션 종료 후 롤백한다.
