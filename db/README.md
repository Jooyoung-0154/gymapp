# DB 적용 안내 — 요구사항 v1.0

2026-11-01 보완: 현재 요구사항·DB 설계 문서는 v1.1이다. 정적 검사와 PostgreSQL 15.19에서의 스키마·기본 스모크 실행이 통과했다. v1.1 정책 전체·동시성·최소권한·복구 검증은 남아 있다. 최신 결과는 `검증결과.md`, 전체 상태는 `../프로젝트현황.md`를 따른다. `.validation`의 pglast는 Python 3.12용이다.

## 이 PC의 개발 DB

`pwsh -NoProfile -File tools/start-dev-db.ps1`로 프로젝트 전용 개발 서버를 시작/확인한다. `127.0.0.1:55432`의 `gym_dev`이며, 설치 시 만들어진 5432 포트 서버와 분리되어 있다. 자동 생성 자격증명과 데이터는 버전 관리에서 제외한 `.validation/dev-postgres/`에만 둔다. 개발 DB 소유자 계정은 향후 업무 API용 최소권한 계정을 대신하지 않는다.

`-Validate` 옵션은 빈 DB 최초 생성 시에만 스키마·스모크를 적용한다. 기존 gym 스키마가 있으면 중단하며 삭제하지 않는다. 아래 일반 적용 예시는 다른 신규 개발 DB를 준비할 때 참고한다.

`001_schema.sql`은 새 요구사항을 반영한 PostgreSQL 15+ 신규 DB용 기준이다. `btree_gist`, `pg_trgm` 확장 설치 권한이 필요하다. 기존 SQL/설계/테스트는 `archive/v0.1/`에 보관했다.

## 파일

| 파일 | 목적 |
|---|---|
| `001_schema.sql` | 테이블·관계·상태·구간 제약·인덱스·조회 뷰·핵심 트리거 |
| `002_smoke_test.sql` | 개발 DB에서 자정 출석·구간·PT 충돌·휴회 유지 등 검사 후 롤백 |
| `validate_sql.py` | pglast를 이용한 SQL/PL/pgSQL 문법 검사 |
| `검증결과.md` | 수행한 검증과 미수행 검증 |
| `../DB설계서.md` | ERD·테이블 사전·업무 트랜잭션·접근/파기 책임 |

## 신규 개발 DB 적용

프로젝트 루트에서 개발 DB 연결을 `DATABASE_URL`에 설정한 다음 실행한다.

```powershell
psql "$env:DATABASE_URL" -v ON_ERROR_STOP=1 -f db/001_schema.sql
psql "$env:DATABASE_URL" -v ON_ERROR_STOP=1 -f db/002_smoke_test.sql
```

스키마 생성은 한 트랜잭션이다. 기존 `gym`/`gym_private`가 있으면 실패하며 삭제하지 않는다. 두 번째 파일은 개발 DB에서만 사용한다. ROLLBACK해도 시퀀스 번호 소모는 되돌아가지 않는다.

v0.1을 이미 적용했다면 새 파일을 그대로 실행하지 않는다. 기존 데이터·버전 확인 후 변환 스크립트가 필요하다. 이번 작업은 파일 재작성이며 운영 DB 접속·삭제·데이터 이전은 수행하지 않았다.

## 초기 운영 준비

1. 배포 담당자가 KMS·전화번호 정규화/HMAC·비밀번호 전용 해시를 구성하고 최초 운영자와 MFA를 등록한다. 초기 계정/비밀번호는 SQL에 넣지 않았다.
2. 운영시간·휴무·혼잡 기준·휴회 한도·연락처·시설/PT 이용권·트레이너·슬롯을 입력한다. 임의 인원·휴회 한도는 시드하지 않았다. 알림 종류와 개인정보 없는 공통 푸시 문구만 시드했다.
3. 정의서 v1.0 정책 스냅샷을 policy_versions에 등록하고 새 예약·기간 변경·개근 평가가 적용 버전을 참조하게 한다.
4. API 서버는 최소 권한 역할, 분리보존은 별도 역할, 파기는 `gym_purger` NOLOGIN 그룹에 속한 전용 작업 계정으로 구성한다. SQL은 전역 역할·로그인 자격증명을 생성하지 않는다. 업무 서버를 DB 소유자/파기 역할로 실행하지 않는다.
5. QR·즉시 개근 보상·예약/확보·차감·기간 조정은 설계서의 잠금/트랜잭션 규약으로 구현한다. DDL 자체는 모든 업무 처리를 실행하는 프로그램이 아니다.
6. 자정 개근, 1분 차감·알림·혼잡도, 탈퇴·기한 만료 파기, 복구 대조 작업과 백업을 별도로 배포한다.

## 권한과 이력

PUBLIC 권한은 철회했다. RLS는 아직 구성하지 않았다. 사용자별 범위는 인증된 API에서 확인하고 사용자 기기에 DB 계정을 배포하지 않는다. 접속/권한 이력은 `gym_private`로 분리하고 일반 프로필·일지의 무기한 보존 근거로 사용하지 않는다.

일반 원장 변경은 금지하되 적법한 파기를 위한 별도 경로를 둔다. 실제 키 삭제·원문 정정·서비스 기록 파기·백업 선택적 파기는 KMS·파기 작업·저장소와 결합해야 한다. 삭제 대장만 기록하는 것으로 파기 완료가 되지 않는다.

PostgreSQL 구간 배제 제약은 [공식 범위형 문서](https://www.postgresql.org/docs/15/rangetypes.html), 확장은 [btree_gist 문서](https://www.postgresql.org/docs/15/btree-gist.html)를 따른다.
