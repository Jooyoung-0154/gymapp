# PostgreSQL 물리 설계 초안

요구사항정의서 v0.11과 DB설계서 v0.1을 기반으로 작성했다. PostgreSQL 15 이상을 대상으로 하며 `btree_gist` 확장 설치 권한이 필요하다. DB 선택은 이번 단계의 구현 제안이다.

## 적용

새 개발 DB에서 프로젝트 루트를 기준으로 실행한다.

```powershell
psql "$env:DATABASE_URL" -v ON_ERROR_STOP=1 -f db/001_schema.sql
psql "$env:DATABASE_URL" -v ON_ERROR_STOP=1 -f db/002_smoke_test.sql
```

이 파일은 `gym` 스키마를 처음 만드는 1회용 마이그레이션이다. 기존 스키마가 있으면 실패하며 기존 데이터를 삭제하지 않는다. 연결 문자열에는 해당 개발 DB를 지정한다. 트랜잭션 안에서 생성하므로 오류가 나면 생성 작업 전체가 취소된다. 확장 설치도 환경에서 허용되어야 한다.

회원·운영자·기기·회원권·정책 데이터는 넣지 않았다. `gym_settings`의 시간대를 명시적으로 등록해야 출석을 생성할 수 있다. 영업일 달력과 승인 정책도 운영자가 결정한 값으로 등록한다. 기본 정책이나 자동 지급 작업은 실행하지 않는다.

## 이번 SQL에서 보장하는 범위

- 기본키·외래키·상태·날짜·횟수 제약 및 주요 조회 인덱스.
- 동일 기기·요청 키 중복 금지, 같은 회원의 유효한 2시간 방문 구간 중복 금지.
- 한 트레이너의 점유 예약 시간 겹침 금지, 수업 구간 1시간.
- 예약과 담당자 배정의 회원·트레이너 일치, PT 계좌와 예약의 회원 일치.
- 보상 주기별 지급 중복 금지, 휴회·보상 기본 연장 중복 금지, 예약 기본 차감 중복 금지.
- 원장·감사 이력의 UPDATE/DELETE 거부. DB 소유자는 트리거를 해제할 수 있으므로 운영 서비스는 소유자 계정을 사용하지 않아야 한다.
- 출석일을 헬스장 시간대로 산출하고 혼잡도 예정 종료 시각을 입장 +120분으로 산출.

시간 구간 충돌 방지는 PostgreSQL의 범위형과 배제 제약을 사용한다. [공식 범위형 문서](https://www.postgresql.org/docs/15/rangetypes.html), [btree_gist 문서](https://www.postgresql.org/docs/15/btree-gist.html)를 참고했다.

## 서비스 구현에서 반드시 추가할 범위

이 SQL만으로 앱의 모든 업무 규칙이 구현되지는 않는다.

1. 계정 인증·회원별 조회 권한·운영자 권한 검증. 현재 PUBLIC 권한은 주지 않았다. 서버 연결 역할 및 필요 시 RLS는 인증 방식 확정 후 추가한다. 집계 뷰를 회원에게 DB 직접 접근으로 공개하지 않는다.
2. 승인 정책 존재·적용 시각 검증과 정책 내용의 타입 검증. 승인된 정책은 수정하지 않고 새 버전으로 만든다. FK는 승인 상태까지 보장하지 않는다.
3. QR 검증·기기 인증·요청 지문 비교·동일 요청 결과 반환. 구간 중복 오류를 정상 중복 결과로 변환한다.
4. 예약 요청 시 담당자 유효 구간, 트레이너 상태, 가능한 시간, 휴무, 자격 검증. 일정 변경도 트레이너 행 잠금을 사용한다. `occupies_slot`은 대기 예약 점유 정책을 확인해 기록하며 완료/노쇼는 기존 점유를 유지한다.
5. PT 계좌 행 잠금 후 원장과 balance·held_count·hold 상태를 함께 갱신. 복원 원장이 원래 같은 계좌의 차감인지 확인. 원장은 순서·합계까지 자동 검증하지 않는다. 재예약 시 확보 재활성화 정책은 별도 구현한다.
6. 회원권 행 잠금 후 원장·만료일·휴회/보상 상태 동시 갱신. 휴회 대상 회원권과 원장의 일치, 역조정 대상과 일수 일치, 보상 판정 근거 검증. 동일 휴회 후속 변경은 MANUAL 조정과 원래 조정 참조로 관리한다.
7. 개근 평가, 휴무일 건너뛰기, 휴회 초기화, 보상 지급, 정정 후 검토 처리. 같은 회원 잠금과 멱등 키를 사용한다. 과거 이벤트는 수정하지 않고 정정 이벤트를 추가한다.
8. 정확히 24시간 전 취소 허용, 늦은 취소·노쇼 차감, 운영자 면제·복원 처리와 이유 기록.
9. 휴회 승인 구간 중복 검사와 종료일 해석. 회원권 만료/휴회/미래 시작 상태 계산. 중복 회원권은 정책 결정 전 제한하지 않았다.
10. 알림 아웃박스 작업, 소스 버전 재검사, 외부 서비스 멱등 키, 재시도와 처리 중 작업 회수. 채널 미설정은 UNCONFIGURED로 유지한다.
11. visits 변경 시 visit_revisions 작성, 정책·달력·휴회 등 변경 시 audit_logs 작성. 원장 변경 금지 트리거가 감사 행 자동 생성을 대신하지 않는다.
12. 기존 정책/달력·설정 시간대 변경 시 과거 기록 처리. 운영 시작 후 시간대 변경은 별도 데이터 이전 없이 허용하지 않는다.

공통 updated_at/version 자동 갱신은 이번 SQL에서 일괄 구현하지 않았다. version이 있는 테이블은 서비스에서 낙관적 잠금 또는 행 잠금으로 갱신한다. 계정 삭제는 FK로 막고 보관·익명화 정책은 별도로 확정한다.
