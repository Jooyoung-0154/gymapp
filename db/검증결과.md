# DB 설계 v1.0 검증 결과

## 2026-11-01 실제 PostgreSQL 실행 — 통과

- PostgreSQL 15.19(Windows x64) 설치 및 기본 서비스 실행을 확인했다.
- 설치 시 만든 서버와 별도로 프로젝트 전용 서버를 `127.0.0.1:55432`에 만들었다. 데이터 경로는 `.validation/dev-postgres/data`, DB는 `gym_dev`, 소유자는 `gym_dev_owner`다. 프로젝트 개발용 소유자이며 업무 API 계정으로 사용하지 않는다.
- 서버는 루프백 주소에만 수신하며 비밀번호 인증은 SCRAM이다. 자동 생성한 개발 자격증명은 버전 관리에서 제외한 `.validation/dev-postgres/connection.json`에 저장하고 출력하지 않았다. 설치 시 사용자가 정한 비밀번호는 받거나 변경하지 않았다.
- 신규 빈 DB임을 확인하고 `001_schema.sql`을 `ON_ERROR_STOP=1`로 적용했다. 확장 `btree_gist`, `pg_trgm` 생성과 전체 스키마 COMMIT 통과.
- 이어서 `002_smoke_test.sql` 실행: `PASS: membership boundary, midnight attendance, occupancy, PT overlaps, hold bounds, pause preservation, journal author` 메시지와 ROLLBACK 확인.
- 기존 개발 DB의 재접속 통과. `-Validate` 재실행은 기존 gym 스키마를 감지하고 중단하는 것을 확인했다. 기존 데이터를 삭제하거나 스키마를 재적용하지 않았다.
- 아래 과거 `실제 DB 미실행` 절은 2026-10-19 당시 상태다. 최신 실행 상태는 이 절을 따른다.

아직 미검증: 최소권한 업무 계정, 실제 API·서로 다른 연결의 동시 요청, QR·보상 트랜잭션 전체, 자동 작업, KMS·개인정보 파기, 백업 복구, 앱·실기기·부하. 스모크 시험 통과는 요구사항 v1.1 전체 적합성 또는 출시 승인과 다르다.

### 개발 DB 재사용

```powershell
# 처음 만든 DB를 시작/확인한다. 스키마를 다시 적용하지 않는다.
pwsh -NoProfile -File tools/start-dev-db.ps1
```

`-Validate`는 신규 빈 DB에 최초 스키마를 적용할 때만 사용한다. 이미 초기화한 DB의 스모크 재시험은 기존 스키마를 다시 만들지 않고 별도로 실행한다. 자격증명 파일과 데이터 폴더는 공유·커밋하지 않는다.

## 2026-11-01 재실행 기록

현 PC의 번들 Python 3.12.14로 `db/validate_sql.py`를 재실행했다. 외래키 125개, 스키마 112문, 개발 검증 SQL 4문, 테이블 60개 검사 통과. 기본 Python 3.14는 `.validation`의 Python 3.12용 pglast 확장과 호환되지 않아 사용하지 않았다.

실제 PostgreSQL 실행은 여전히 미수행이다. 아래 2026-10-19 기록은 당시 검증 범위이며, 요구사항 v1.1의 전체 실행 검증 완료를 의미하지 않는다.

검증일: 2026-10-19 · 요구사항정의서 v1.0 기준

## 수행한 검증

- PostgreSQL 파서 pglast 8.7로 `001_schema.sql`의 SQL 및 함수/DO 블록 PL/pgSQL 문법을 확인했다.
- `002_smoke_test.sql`의 SQL 및 검증 블록 문법을 확인했다.
- 외래키 대상 테이블·컬럼·컬럼 개수·선언된 PK/UNIQUE 조합을 정적 검사했다. 검사 결과 수치는 최종 실행 출력에 따른다.
- 최종 결과: 테이블 60개·뷰 4개, 외래키 참조 125개 검사 통과. 스키마 SQL 112문·개발 검증 SQL 4문의 SQL/PL/pgSQL 문법 검사 통과.
- 이전 `PAUSE_RESET`·휴회 초기화 정책을 현재 설계에서 제거하고 PAUSE_SKIP 전후 카운트 동일 제약을 넣었다.
- 자정 재스캔과 혼잡도 구간을 분리하고 PT 이용권별 유효기간·확보·차감, 예약 변경 동의, 일지 수정/파기, 알림함/푸시 분리, 법정 분리보존·파기 대장을 요구사항과 대조했다.

## 실제 DB 미실행

현재 PC에서 psql·postgres·Docker 실행 도구가 확인되지 않았다. 실제 PostgreSQL에 스키마/검증 SQL을 적용하거나 데이터 이전·배포하지 않았다. 구문 분석은 확장 설치·트리거 실행·동시 요청·권한·실제 파기의 성공을 뜻하지 않는다.

개발 DB 실행용 검증 SQL은 다음을 검사하도록 작성했다. 이 항목들은 아직 DB 실행 통과 결과가 아니다.

- 종료일 포함 시설 회원권 기간 중복 거절.
- 같은 2시간 구간의 자정 전후 방문을 서로 다른 두 출석일로 인정.
- 정확히 2시간 경과 시 혼잡도 제외, 겹치는 구간 거절·인접 구간 허용.
- 한 트레이너·한 회원의 PT 겹치는 시간 거절.
- 실제 잔액보다 많은 확보 거절.
- 휴회로 7일 카운트를 0으로 변경하는 판정 거절, 7일 유지 허용.
- 일지 작성 트레이너 변경 거절.

테스트는 원 데이터 ROLLBACK을 사용하지만 ID 시퀀스는 소모될 수 있으므로 운영 DB에서 실행하지 않는다. 테스트 계정·정책 값은 스키마 제약 확인용이며 실제 API 자격 검증을 통과하는 운영 데이터로 작성한 것은 아니다.
